# 完整规则

来源：`docs/retrospective-and-skill-rules.md`、`docs/postmortem-cast-window.md`、`docs/settings-must-be-live.md`。执行时以本文件为准；若与旧文档冲突，优先本文件中更严格、且以用户可观察结果为准的条款。

## 需求与对齐

- R-需求可观察：每条需求先写成「用户点哪里、看到什么」。写不出这句，不得进入实现。
- R-歧义先对齐：像「不能随便拖动」这类话，至少有「完全禁止」和「防误触但仍可拖」两种解释。动手前用一句话确认，或给出选项让用户挑。
- R-参考即拆解：出现「参考 / 类似 / 像 XX 那样」，必须先交付竞品拆解表（软件 / 截图 / 控件位置 / 层级 / 交互 / 对照结论），用户确认后再实现。界面验收用截图对比。
- R-先旅程再技术：任何功能先写用户旅程（谁、在哪、做什么），再选技术。
- R-无线优先：涉及连接方式时默认无线优先，USB 只作为兜底。验收参考：从打开电脑端到手机画面出现 ≤ 15 秒，全程可不插线（USB 仅作保底路径）。

## 架构与界面

- R-首屏硬指标：首屏只允许三块——设备列表（含一个主按钮）、一行状态、一个「更多」入口。可交互元素 ≤ 5。新增控件必须同时说明删掉哪个。
- R-核心零业务词：核心代码不允许出现设备或媒体相关业务名词。插件通过 `capabilities` 声明能力；插件可贡献设置项、动作、状态；核心只渲染白名单组件（switch / select / slider / button）。
- R-插件可热增删：插件能力必须能在不重新编译核心的情况下增删。
- R-先确认平台能力：先确认有无现成 API，再决定自研。禁止反复改同一件事先未确认边界的事。
- R-跨进程不子类化：`SetWindowLongPtrW(GWLP_WNDPROC)` 对别的进程窗口无效。要么轮询自绘，要么用系统级 hook。
- R-界面先设计稿：界面需求先出线框或截图，确认后再写代码。
- R-控制台即实时：界面上的每个控件都必须有应用到「正在运行的实例」的路径，并写明延迟和失败提示。写不出来就不要加这个控件。控制台不是「配置文件编辑器」。
- R-设置分级：能实时改的（窗口样式、层级、位置）绝不重启；必须重启的（编码参数）要显示「正在应用」，重启后恢复会话状态。用 `applied: live | restart` 区分，并用 `restarting` 区分「用户关窗」与「主动重启」。
- R-控制台优先可见：新投屏窗口默认不要压住控制台；需要置顶时由用户显式打开。
- R-可观测性：必须有界面内可查看的日志与诊断入口。涉及重启会话的设置，必须评估并度量感知延迟。

## 测试与发布

- R-验收走用户路径：禁止用直接调插件或内核作为交付依据。必须用 UI 自动化点击真实控件（本仓库 `scripts/e2e_cast.ps1`）。
- R-控件必有用例：界面控件的变更必须有自动化用例；没有用例的控件不允许出现在面板上。
- R-测试隔离：跑测试前杀掉旧进程、清理 `settings.json`、清理 WebView2。测试产物不得进入发布 zip。
- R-唯一构建路径：只允许 `npm run tauri -- build`。版本号必须显示在界面上，避免旧进程冒充新版本。`cargo build --release` 不会嵌入前端资源。
- R-发布包默认配置：必须校验默认配置（`lockPosition=false`、`stayAwake=true`）。
- R-门禁：交付前应跑 `powershell -ExecutionPolicy Bypass -File scripts\gate.ps1`。若脚本尚未实现，不得声称门禁已通过。
- R-文档同步：文档与实现同一次提交更新。
- R-可回滚：每个发布包必须能回滚到上一版。

## 流程与措辞

- R-DoD：用户路径可复现；L3 E2E 有对应用例且通过；失败可诊断；门禁全绿（或如实标明门禁未就绪且已完成 3 场景自测）；文档同步。没有通过 DoD 的功能，不允许出现在交付说明里。
- R-单任务流：一次迭代只允许一个「未完成功能」在开发中，其余必须冻结。
- R-三场景自测：交付前必须完成首次使用 / 二次使用 / 异常路径自测，并贴出证据。
- R-禁止过度承诺：禁止说「已修复」。只能说「已验证（附证据）」或「已改，待验证」。
