# 需求卡：同 Wi-Fi Android 无线投屏（华为 / 鸿蒙路径）

- 版本：0.2.0
- 日期：2026-11-16
- 目标设备：HUAWEI Mate 60（BRA-AL00），HarmonyOS 4.2.0 / EMUI 14.2.0，Android 12（API 31）。
- 场景前提：手机与电脑长期连接同一个 Wi-Fi；USB 只用于首次开通和兜底。
- **重要事实**：鸿蒙 4.x 的「开发人员选项」中没有「无线调试」，这是正常现象。本版本不做 `adb pair` / 配对码 / 二维码流程。

## 目标

用户首次用数据线连接手机，点一次「一键开启无线」，电脑执行 `adb tcpip 5555` 并通过同一 Wi-Fi 的 `IP:5555` 连接；之后拔掉数据线即可投屏。再次打开应用时自动/一键重连，失败时给出可执行原因。

## 用户旅程

### 首次使用（华为 / 鸿蒙）

- 谁：普通用户，手机在电脑旁，未插线。
- 在哪：电脑桌面；手机与电脑连接同一个 Wi-Fi。
- 第一步：打开 CastPane。首屏显示「设备」、一个主按钮和一行状态；没有设备时，在设备区内联显示 3 条首次开通步骤。
- 之后：手机「设置 → 系统和更新 → 开发人员选项」打开「USB 调试」（建议同时打开「仅充电模式下允许 ADB 调试」）→ 数据线连接电脑 → 手机点「允许」→ 回到应用点「一键开启无线」。
- 结束时看到：进度层三步「读取手机 Wi-Fi 地址 → 开启 5555 无线端口 → 连接并启动画面」；成功后状态行「正在投屏 · <手机名> · 可拔线」，设备行变为「无线 · 同一 Wi-Fi」；数据线可以拔掉。

### 二次使用（已开通，同一 Wi-Fi）

- 打开应用后，3 秒内自动 `adb connect <上次 IP>:5555`；设备行显示「已连接」，主按钮为「开始投屏」。
- 点一次「开始投屏」，≤ 15 秒出现画面。
- 如果手机换了 Wi-Fi 或路由器重新分配 IP，自动重连失败；状态行提示「手机重启或切换网络后，tcpip 会失效；插一次数据线，点『一键开启无线』即可恢复」。

### USB 兜底

- 手机插线，但无线连接不可用时，首屏显示 USB 设备行，主按钮「一键开启无线」；也可以从「更多 → 用 USB 直接投屏」立即投屏。
- 首次开通失败（端口占用、手机未连 Wi-Fi、网段不同）时，进度层保留错误原因，并提供「重试」「直接用 USB 投屏」「关闭」。

### 异常路径

| 情况 | 用户看到 | 下一步 |
|---|---|---|
| 没开 USB 调试 | 状态行「请用数据线连接手机一次」；设备区 3 条步骤 | 按步骤打开 USB 调试 |
| USB 未授权 | 状态行「USB 调试未授权 · 请在手机上点『允许』」 | 手机上点允许；建议开「仅充电模式下允许 ADB 调试」 |
| 手机没连 Wi-Fi | 进度层「手机没有连接 Wi-Fi」 | 手机连到与电脑相同的 Wi-Fi |
| 手机与电脑不同网段 | 状态行「手机与电脑不在同一 Wi-Fi」；网络徽标「网络不同」 | 连接同一个 Wi-Fi |
| 手机重启后 tcpip 失效 | 状态行「<手机> 的无线连接已失效」 | 插一次数据线，点「一键开启无线」 |
| 端口 5555 被占用 | 进度层「USB 转无线失败」+ 端口提示 | 关闭占用程序或重插后重试 |
| 投屏中设备掉线 | 状态行「设备已掉线 · 请检查 Wi-Fi 后重连」 | 检查 Wi-Fi；必要时插线重新开通 |
| 缺少 scrcpy / adb | 「更多 → 诊断」显示引擎路径与修复提示 | 运行 `scripts/fetch-engines.ps1` |

## 成功标准（可观察）

| # | 操作 | 时限 | 可见结果 |
|---|---|---|---|
| 1 | 打开应用 | 立即 | 首屏默认是「设备 + 主按钮 + 一行状态 + 更多」，不出现「请打开无线调试」 |
| 2 | 数首屏可交互元素 | — | ≤ 5 个；本版本实际为 2–3 个（更多、设备行、主按钮） |
| 3 | USB 一键开启无线 | ≤ 15 秒 | 进度层三步完成；状态行「正在投屏 · … · 可拔线」；设备行变为无线；scrcpy 的 `-s` 为 `IP:5555` |
| 4 | 已开通设备二次打开 | ≤ 3 秒列出 | 自动重连成功，设备行「已连接」；点一次即可投屏 |
| 5 | 投屏启动 | ≤ 15 秒 | 出现 scrcpy 窗口，标题栏含 `CastPane -`；状态行「正在投屏」 |
| 6 | 失败 | 立即 | 状态行给出一句可执行原因；「更多 → 诊断」有 adb 原始输出 |
| 7 | 投屏中掉线 | ≤ 3 秒 | 状态行变为掉线原因，主按钮恢复为可重试 |
| 8 | 首次开通后拔线 | 立即 | 画面不中断（scrcpy 使用 `IP:5555`，不依赖 USB） |

## 非目标

- 不做 Android 11+「无线调试 / adb pair / 配对码 / 二维码」流程（鸿蒙没有该入口）。
- 不做 AirPlay 真机验证、Miracast、DLNA。
- 不做屏幕亮度之外的新媒体能力；不修复 Android 12 音频转发限制。
- 不做跨网段/公共 Wi-Fi/AP 隔离自动打洞。
- 不做统一优化 backlog（窗口拖动、插件化重构、gate.ps1 全面门禁）。
- 不自动改手机的 USB 模式；首次仍需要用户插线并允许调试。

## 歧义确认（用户不在场，本轮自选）

| 原话 | 解释 A | 解释 B | 本轮选择 |
|---|---|---|---|
| 「首屏只保留必要块」 | 设置全部进「更多」 | 首屏保留常用开关 | 选 A。首屏 0 个调试控件 |
| 「USB 只作首次开通和兜底」 | USB 设备永不显示 | 无无线时显示 USB 行，标明首次开通 | 选 B |
| 「自动重连」 | 静默重连不提示 | 自动尝试并显示状态 | 选 B |
| 「一键开启无线」 | 只开启端口，用户再点投屏 | 开启、连接、启动画面一次完成 | 选 B（步骤最短），并在进度层逐步显示 |
| 「断线后」 | 自动无限重试 | 显示原因，用户点重试/插线 | 选 B，避免在手机重启后空转 |

以上选择按用户「自行选定默认方案并实现，不要停下来等待确认」执行；需拍板的点见交付说明。

## 能力边界

| 能力 | 平台现成 API | 结论 |
|---|---|---|
| 发现 USB 手机 | `adb devices -l` | 能用 |
| 读取手机 Wi-Fi IP | `adb -s <usb> shell ip route` | 能用 |
| 开启无线端口 | `adb -s <usb> tcpip 5555` | 能用；手机重启/切网后失效 |
| 连接无线 | `adb connect <ip>:5555` | 能用；需同一网段 |
| 投屏 | scrcpy v5.0.1，`-s <ip>:5555` | 能用；已验证 Wi-Fi 串口+窗口 |
| 判断同网段 | IPv4 /24 比较 | 能用（不做跨网段） |
| 记住上次 IP | 插件状态文件 `%LOCALAPPDATA%\CastPane\android-wireless.json` | 能用 |
| 自动打开 USB 调试 | Android/HarmonyOS 不提供第三方 API | 不能用，只能引导 |
| 读取配对码/无线调试 | 鸿蒙无此入口 | 不做 |
| 端口 5555 被占用 | 无系统 API 预检；`adb connect` 失败后提示 | 需兜底提示 |

## 界面

- 竞品拆解表：见 [wireless-cast-competitor-teardown.md](wireless-cast-competitor-teardown.md)。
- 线框图：`docs/assets/wireless-wireframe.png`（源 `docs/design/wireless-wireframe.html`）。
- 首屏可交互元素（≤ 5）：
  1. 「更多」入口。
  2. 设备行（无线 / USB / 上次连接，最多 3 行，每行可选中）。
  3. 主按钮（检测手机 / 一键开启无线 / 开始投屏 / 停止投屏 / 重新连接 / 重新检测）。
- 删除的旧元素：
  - 首屏 AirPlay 整卡 → 移入「更多 → 其他设备」。
  - 首屏全部开关/滑块/日志 → 移入「更多」。
  - 首屏「扫描设备」小按钮 → 主按钮 + 自动轮询。
  - 每个设备行的「投屏」小按钮 → 合并为一个主按钮。
  - 配对码 / 二维码向导 → 不做。
- 进度层不属于首屏；只有「重试 / 直接用 USB 投屏 / 关闭」三个错误态动作。

## 验收环境说明

- 本轮可用真机：HUAWEI BRA-AL00 / HarmonyOS 4.2.0 / Android 12。
- 真机已在 2026-11-16 凌晨通过 `adb tcpip 5555` + `adb connect 192.168.101.5:5555` 验证：`adb devices` 只显示无线串口，scrcpy 窗口在 1.4 秒内出现；之后为测试 USB 首次路径执行 `adb usb`，手机进入 USB 模式且当前 Windows 未重新枚举到 USB 设备，因此**本轮未能跑通“UI 点击一键开启无线 + 真机画面”的完整真机链路**。
- 该链路用可编程 mock adb + mock scrcpy 做了 L2 协议测试和 L3 UI 点击测试；交付说明中如实标注“已改，待真机验证”的部分。
