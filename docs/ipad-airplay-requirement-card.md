# 需求卡：iPad / iPhone AirPlay 投屏（v0.3.0）

- 日期：2026-11-16
- 目标：同一 Wi-Fi 下，iPad / iPhone 在控制中心点「屏幕镜像」，能看到并选择本机接收端，随后在独立画面窗口看到镜像画面。
- 交付顺序：本轮先做 AirPlay，再做文件互传。
- 现场检查（写卡前已完成）：
  - 电脑：`WLAN`，SSID `HUAWEI-10EP0W`，IP `192.168.101.6`，网关 `192.168.101.1`。
  - 局域网扫描：ping 全网段 + ARP + mDNS（`_airplay._tcp` / `_companion-link._tcp` / `_apple-mobdev2._tcp`）未发现 Apple 设备；在线设备只有路由器、Mate 60（`192.168.101.5`）、两台海尔家电、一台 E-Life 设备。
  - 结论：**本轮 iPad 不在场 / 未接入同一 Wi-Fi**。接收端必须做成完整可用，验收按「已改，待真机验证」记录；真机画面证据本轮不能伪造。
  - 华为 Mate 60 无线 ADB `192.168.101.5:5555` 为 `device`，全程不得执行 `adb usb` 或断开它。

## 目标

用户不需要命令行、不需要找「更多」：打开 CastPane 就能看到「iPad / iPhone 投屏」入口；点一次启动接收端，按页面上的一句话在 iPad 控制中心选择 `CastPane`，画面出现在独立窗口中；可随时停止接收端。

## 用户旅程

- 谁：普通用户，iPad 在电脑旁，二者连同一个 Wi-Fi。
- 在哪：电脑桌面；iPad 未插线；接收端与 iPad 同网段。
- 第一步：打开 CastPane，首屏设备区看到两行：已连接的华为手机、`iPad / iPhone 投屏`（AirPlay）。
- 之后：点 `iPad / iPhone 投屏` → 主按钮变 `启动接收端` → 点一次。
- 页面上看到：大标题「iPad 投屏」，状态「接收端已启动 · 等待 iPad」，接收端名称 `CastPane`、电脑 IP，以及三步：
  1. 确认 iPad 与电脑连同一个 Wi-Fi。
  2. iPad 从右上角下滑打开控制中心，点「屏幕镜像」。
  3. 在列表中选择 `CastPane`。
- 结束时看到：独立投屏窗口出现 iPad 画面（窗口标题含 `CastPane`，可拖动/最小化/关闭）；CastPane 页面状态变为「iPad 已连接 · 正在投屏」。
- 停止：点 `停止接收端`，窗口关闭，页面回到「接收端未启动」；iPad 控制中心的 `CastPane` 随之消失。

## 成功标准（可观察）

| # | 操作 | 时限 | 可见结果 |
|---|---|---|---|
| 1 | 打开 CastPane | 首屏立即 | 设备区出现 `iPad / iPhone 投屏`，不需要进「更多」；首屏可交互元素 ≤ 5 |
| 2 | 选中 AirPlay 行 | 立即 | 主按钮为 `启动接收端`；状态行一句话说明去 iPad 控制中心 |
| 3 | 点 `启动接收端` | ≤ 6 秒 | 页面进入等待态；本机 mDNS 广播 `_airplay._tcp` 名称 `CastPane`；接收端进程监听 TCP 端口 |
| 4 | 在 iPad 控制中心选 `CastPane` | ≤ 8 秒 | 独立画面窗口出现；CastPane 状态变「iPad 已连接」 |
| 5 | 点 `停止接收端` | ≤ 3 秒 | 进程退出、mDNS 记录消失、窗口关闭；状态回「未启动」 |
| 6 | 引擎缺失 | 立即 | 页面说人话：「AirPlay 接收引擎没有安装」，给出重新安装入口与路径，不出现黑窗 |
| 7 | Bonjour 缺失 | 立即 | 页面提示「首次使用需要 Bonjour 发现服务」，提供「安装接收组件」按钮；不静默失败 |
| 8 | 端口/防火墙异常 | ≤ 8 秒 | 页面提示「接收端没有开始监听：端口被占用或防火墙阻止」，并给诊断入口 |
| 9 | iPad 没选本机 | 持续 | 等待态文案明确「还没有设备连接 · 在控制中心选择 CastPane」，不假装已投屏 |
| 10 | 关闭画面窗口 | 立即 | 接收端继续等待，iPad 可重新连接；不把「关窗」当成应用崩溃 |

## 非目标

- 不做 AirPlay 2 多房间音频、Apple TV 遥控、DRM 视频。
- 不做 Android Miracast / DLNA。
- 不做后台开机自启接收端（仍由用户点一次）。
- 不改动华为安卓无线投屏路径；不引入 `adb pair` / 配对码 / 无线调试。
- 不做 iOS 真机画面以外的协议仿真冒充验收。

## 歧义确认（用户不在场，本轮自选）

| 原话 | 解释 A | 解释 B | 选择 |
|---|---|---|---|
| 「iPad 投屏要能被找到」 | 放「更多」里加一行 | 首屏设备区直接一行 | 选 B；「更多」只保留设置 |
| 「不要只藏着不做成可用闭环」 | 只做引擎启动 | 启动/等待/连接/停止/失败全闭环 | 选 B |
| 「可关可停」 | 只关画面窗口 | 关窗口后接收端继续等待，另有停止接收端 | 选 B（更符合投屏习惯） |
| AirPlay 失败提示 | 只打日志 | 页面一句人话 + 诊断 | 选 B |

## 能力边界

| 能力 | 平台现成 API / 事实 | 结论 |
|---|---|---|
| AirPlay 接收 | `uxplay-windows 2.0.0.1736`（GPL-3.0） | 能用；本机已装并校验 SHA-256 |
| mDNS 广播 | Windows 需 Bonjour 服务；uxplay 自带 `mDNSResponder.exe` + `dnssd.dll` | 能用；本机已安装并运行 `Bonjour Service` |
| 引擎缺少 GStreamer scanner | 发布 zip 缺 `libexec/gstreamer-1.0/gst-plugin-scanner.exe`，导致 H.264/视频 sink 无法装载 | 需补齐；已从 MSYS2 GStreamer 1.28.1 补入并校验 |
| 接收端状态 | 可见画面窗口（按 PID 枚举）+ 进程存活 | 能用；窗口出现=已连接，窗口消失=等待 |
| 停止 | 杀进程树（含蓝牙 beacon） | 能用 |
| 发现 iPad 是否同 Wi-Fi | 无 API 可查对端 Wi-Fi；只能显示本机 SSID/IP 并给步骤 | 不能自动判定；文案不撒谎 |
| 安装 Bonjour | `mDNSResponder.exe -install`（需要管理员/UAC） | 需自研按钮 + 提示；本机已装 |
| 防火墙放行 | Windows 防火墙规则需要管理员 | 需提示；本轮不静默改系统 |

## 界面（若涉及）

- 竞品拆解：见 [ipad-airplay-competitor-teardown.md](ipad-airplay-competitor-teardown.md)（含截图）。
- 设计稿：`docs/design/v03-wireframe.html` / `docs/assets/v03-wireframe.png`。
- 首屏新增：设备区多一行 `iPad / iPhone 投屏`（AirPlay）；不新增首屏按钮。
- 首屏可交互元素（≤ 5）：`更多`、华为设备行、AirPlay 行、主按钮、（仅已连接手机时）状态行内 `文件` 入口。
- 为新增控件删掉的元素：设备行从最多 3 行降到 2 行；AirPlay 不再只藏在「更多 → 其他设备」。
- 二级页：`iPad 投屏` 页（状态 + 三步 + 启动/停止 + 诊断/安装）与 `文件互传` 页；二级页不占首屏。
