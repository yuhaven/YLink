# 待统一处理的问题与优化项

- 本轮只推进一件事：同 Wi-Fi 下的 Android 无线投屏可用闭环。

## 本轮进行中（不要当作已完成）

- 无线投屏此前未实现，只停留在方案文档。0.2.0 已按华为 / 鸿蒙实际能力实现：USB 一次 `adb tcpip 5555` → 同一 Wi-Fi 自动/一键重连，不做配对码。交付证据见 `docs/wireless-cast-delivery.md`。

## 产品与体验（延后统一优化）

- 极简主义未达标：首屏控件偏多，窗口内容仍可能需要滚动；缺少稳定的信息架构，新需求容易直接往首屏加行。
- 插件化不完整：目前主要体现在进程隔离（独立 exe + JSON-RPC），UI 与能力还没有真正可插拔；「能力可增删、界面可裁剪」尚未达成。
- 屏幕亮度控制从未实现，现有的只是「保持亮屏（stayAwake）」，且曾被配置关掉。
- 音频无法在当前测试机上转发：手机为 Android 12（API 31），scrcpy 音频需要 API 33+。PC 侧静音/取消静音层也未做。
- 竖屏锁定的 App（阅读/短视频等）旋转后不会重新排版，容易被误判为旋转坏了，需要更清楚的说明或引导。
- AirPlay（iPhone / iPad）链路待真机验证，引擎曾因下载失败搁置。
- 拖动热区 / 旋转按钮等细节的视觉提示仍偏弱（例如早期顶部 12px 拖动条无提示）。部分窗口行为已改回原生标题栏，但仍需统一视觉。

## 质量与工程（延后统一优化）

- `scripts/gate.ps1` 门禁脚本尚未实现（清理环境 → 测试 → 打包 → E2E → 校验发布包默认配置）。
- 滑块等设置的「应用到当前会话」已补过，但界面自动化覆盖仍不完整。
- 打包与产物校验不足：曾出现 dist 里是旧插件、测试写入的 `settings.json`（如 `lockPosition=true`）被打进发布包。
- README 与实现可能不同步（例如「总在最前」等后续已删除或改过的行为）。
- 可观测性不足：排查仍较依赖 `%TEMP%\castpane.log`，界面内诊断需加强。
- 性能未系统度量：轮询间隔、设置变更重启会话带来的黑屏/延迟，还没有验收基线。
- 缺少版本与回滚记录，多次靠重新打包覆盖。
- 异常路径未统一补全：杀软拦截、无管理员权限、端口占用、设备掉线等，多是遇到再补。
- localStorage 影子状态已改为以 `settings.json` 为唯一来源，仍需回归确认没有残留覆盖。
