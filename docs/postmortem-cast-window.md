# 复盘：投屏窗口拖动 / 横屏 / 「点了没窗口」

日期：2026-11-15 ｜ 影响版本：v0.1.0 ｜ 状态：已修复并加了自动化验收

## 一、用户看到的现象

1. 投屏窗口**拖不动**
2. 切到「横屏」后**画面仍是竖屏**
3. 点「投屏」后**没有窗口出现**

## 二、直接原因（逐个）

### 1. 拖不动

为了去掉标题栏，插件把窗口样式里的 `WS_CAPTION / WS_THICKFRAME / WS_SYSMENU` 全部剥掉了。没有了标题栏，Windows 就没有可拖拽的命中区域——**去边框和可拖动在 Win32 里是互斥的**，我当时只做了前者。

第一次修复尝试用 `SetWindowLongPtrW(hwnd, GWLP_WNDPROC, ...)` 子类化窗口去返回 `HTCAPTION`。**这个 API 不能跨进程使用**：窗口属于 scrcpy 进程，调用线程不是它的 UI 线程，调用静默失败（返回 0），命中测试从未生效。

最终方案：插件自己实现拖动——16ms 轮询鼠标左键与光标位置，若按下的位置在窗口顶部 12px 条带内，就进入拖拽态，随后用 `SetWindowPos` 跟随光标。跨进程可行，且不影响画面区域的 scrcpy 触控。

### 2. 横屏无效

产品逻辑本身是对的（`orientation` → `--capture-orientation=@90`），问题出在**状态被污染**：

- 我的自动化脚本在操作界面时把 `settings.json` 写成了 `{"orientation":"auto", ...}`，之后人工打开就是 auto，自然不旋转。
- 第一次写 E2E 时按“第一个值像 portrait/landscape/auto 的下拉框”定位，结果选中了 **AirPlay 卡片的「渲染器」**（值恰好是 `auto`），方向设置根本没被点到。

教训：**测试必须精确定位控件，且必须清理状态**。

### 3. 点了没有窗口

两个独立原因，都出在“我给你的那个 exe 不对”：

- **单实例 + 旧进程**：旧的 CastPane 还在跑，双击新 exe 只会把旧窗口叫到前台，用户点的还是旧版本。
- **打包用错命令**：`cargo build --release` 不会把前端资源嵌进 exe，产物会去连 `http://localhost:1420`，即开发服务器。必须用 `npm run tauri -- build`。我自己也在这上面栽过一次：手动 `cargo build` 覆盖后又复制进 dist，把好好的包弄坏了。

现在 UI 左上角显示版本号（`v0.1.0 · 2 个插件`），并且 `package.ps1` 只走 Tauri CLI。

## 三、深层原因：任务拆解错了

这是这次最该记住的部分。

| 我理解的 | 用户实际要的 | 差在哪 |
|---|---|---|
| “窗口不能随便拖动” → 完全固定 | 平时能拖，但不要误触；可选锁定 | 把“防误触”做成了“禁止” |
| “横竖屏切换” → 插件支持参数 | 界面上选一下，投出来就是那个方向 | 只验证了插件层，没验证 UI 层 |
| “投屏成功” → 插件能拉起 scrcpy | 用户点按钮 → 出现窗口 → 能看 | 验证路径和用户路径不是同一条 |

根因一句话：**把“功能点”当成了“用户可观察的行为”去验收。**

## 四、经验规则（后续开发强制执行）

**R1 · 验收标准必须是用户路径**
每条需求先写成“用户点哪里、看到什么”，例如：“点『投屏』后 3 秒内出现窗口，宽高比 2.2 左右”。写不出这句，说明需求没拆清。

**R2 · 测试脚本必须走同一条路径**
禁止用“直接调插件/直接调内核”的方式作为交付依据。必须用 UI 自动化点击真实控件（本仓库 `scripts/e2e_cast.ps1`）。

**R3 · 有歧义先对齐再动手**
“不能随便拖动”这类表述至少有两种解释（禁止 vs 防误触）。动手前用一句话确认，或给出两个可选行为让用户挑。

**R4 · 测试要隔离状态**
跑测试前：杀掉旧进程、清 `settings.json`、清 WebView2 进程。否则测的是上一轮的状态。

**R5 · 产物只有一条构建路径**
只允许 `npm run tauri -- build`；版本号必须显示在界面上，避免“旧进程冒充新版本”。

**R6 · 跨进程窗口不要子类化**
`SetWindowLongPtrW(GWLP_WNDPROC)` 对别的进程的窗口无效。要么轮询自绘，要么用系统级 hook。

## 五、现在的验收结果

`scripts/e2e_cast.ps1` 会启动打包好的应用，用 UI Automation 改「画面方向」、点「投屏」、再用模拟鼠标拖动窗口，全部自动判定：

| 用例 | 结果 |
|---|---|
| 横屏：`-Orientation landscape` | PASS，窗口 2176×983，ratio 2.214，拖动 x 192→336 |
| 竖屏：`-Orientation portrait` | PASS，窗口 553×1224，ratio 0.452，拖动 x 935→1079 |

命令：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\e2e_cast.ps1 -Orientation landscape
powershell -ExecutionPolicy Bypass -File scripts\e2e_cast.ps1 -Orientation portrait
```

## 六、遗留与后续

- 拖动条带目前是顶部 12px，无视觉提示；后续可以画一条 2px 的浅色分隔线。
- `orientation` 改动要重新点一次「投屏」才生效；后续可做成切换即重启会话。
- 设置里 `maxSize/maxFps` 曾出现 2160/120 的旧值（来自 localStorage），说明文件与 localStorage 的优先级需要再理一遍。
