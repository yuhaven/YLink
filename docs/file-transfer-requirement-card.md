# 需求卡：电脑 ↔ 手机文件互传（v0.3.0）

- 日期：2026-11-16
- 目标：在已连接的华为 Mate 60（优先当前无线 ADB `192.168.101.5:5555`）与电脑之间浏览、发送、接收文件，双向可用，有进度和明确失败原因。
- 复用：现有 `adb.exe`（scrcpy 自带，Apache-2.0），不新增闭源工具，不要求用户再开「无线调试」。
- 前提：手机已通过现有无线/USB ADB 连接为 `device`；文件互传不得中断投屏会话。

## 目标

用户在 CastPane 首屏看到已连接手机后，点一次 `文件` 进入二级页；能看到手机目录（照片、视频、文档、普通文件夹），把文件下载到电脑，或从电脑发送文件/文件夹到手机；传输中有进度，完成/失败都有原因和落盘路径。

## 用户旅程

### 首次使用（已连接手机）

- 谁：普通用户；华为 Mate 60 已无线连接（`192.168.101.5:5555`）。
- 在哪：CastPane 首屏；手机与电脑同一 Wi-Fi。
- 第一步：设备行显示「无线 · 同一 Wi-Fi」；状态行右侧出现 `文件`。
- 之后：点 `文件` → 文件页默认显示手机 `/sdcard`，顶部面包屑与「发送到手机」按钮。
- 浏览：点 `DCIM` / `Download` / `Documents` 等文件夹进入；点 `..` 或面包屑返回；文件行显示名称、大小、日期。
- 接收：勾选一个文件 → 点 `下载到电脑` → 传输卡片显示文件名、进度、速度；完成后显示「已保存到 …\Downloads\CastPane\文件名」，并可点 `打开文件夹`。
- 发送：点 `发送到手机` → Windows 文件选择框选文件（或把文件拖进窗口）→ 传到当前手机目录；进度、成功、失败原因可见。
- 结束时看到：手机端文件出现在 `/sdcard/Download/CastPane/`（或当前目录）；电脑端文件在 `Downloads\CastPane\`；大小一致。

### 二次使用

- 再次进入文件页，默认回到上次浏览的目录（本次会话内）；传输记录保留最近 5 条。
- 无线投屏正在运行时进入文件页，投屏窗口不关闭；退出文件页后仍可继续投屏。

### 异常路径

| 情况 | 用户看到 | 下一步 |
|---|---|---|
| 手机掉线 | 「手机已离线；请确认同一 Wi-Fi」 | 回首页重连 |
| `/sdcard/Android/data` 权限拒绝 | 「系统限制此目录，请换到 Download 或 DCIM」 | 换目录 |
| 手机存储满 | 「手机存储空间不足」 | 清理空间 |
| 文件被占用/不存在 | 「文件已不存在或无法读取」 | 刷新列表 |
| 大文件传输中断 | 「传输中断：…；已保留的部分文件在 …」 | 重试 |
| 目标文件已存在 | 自动改名 `name (1).ext`，不覆盖 | 继续 |
| 没有选择文件 | 按钮禁用/提示「先选择一个文件」 | 选择文件 |
| ADB 未授权 | 「ADB 未授权；请在手机上点允许」 | 回首页按 USB 引导 |

## 成功标准（可观察）

| # | 操作 | 时限 | 可见结果 |
|---|---|---|---|
| 1 | 已连接手机点 `文件` | ≤ 2 秒 | 文件页打开，显示 `/sdcard` 目录列表与设备名 |
| 2 | 浏览 `DCIM` / `Download` | 每次 ≤ 3 秒 | 文件夹优先排序，路径面包屑正确，文件名/大小/日期可见 |
| 3 | 电脑 → 手机 | 10 MB 文件 ≤ 30 秒 | 进度从 0 到 100%，手机端文件大小一致；耗时显示 |
| 4 | 手机 → 电脑 | 10 MB 文件 ≤ 30 秒 | 进度从 0 到 100%，电脑端文件大小/哈希一致；路径显示 |
| 5 | 大文件 | 100 MB 不静默卡死 | 进度持续变化；可看到速度与已传字节 |
| 6 | 文件夹 | ≤ 30 秒（小目录） | 可进入/下载/发送；失败给权限原因 |
| 7 | 投屏中互传 | 传输全程 | scrcpy 窗口仍在，会话不掉线 |
| 8 | 失败 | 立即 | 一句话原因 + 可重试；不出现「已发送」假成功 |

## 非目标

- 不做云盘中转、跨公网传输、二维码配对、账号登录。
- 不做手机端安装 App；只走 ADB。
- 不申请「所有文件访问」/ROOT；不碰 `/data`、`/system`。
- 不做后台自动同步、断点续传（本轮只保留部分文件并提示）。
- 不改华为无线投屏的 `tcpip 5555` 路径。

## 歧义确认（用户不在场，本轮自选）

| 原话 | 解释 A | 解释 B | 选择 |
|---|---|---|---|
| 「浏览、发送、接收」 | 只做发送/接收两个弹窗 | 加手机目录浏览 | 选 B；浏览是「接收哪个文件」的前提 |
| 「作为已连接设备上的明确入口」 | 设备行内第二个按钮 | 状态行右侧 `文件` 小入口 | 选状态行入口；设备行保持单选，不加第二个行内按钮 |
| 「接收文件」 | 手机主动推送到电脑 | 电脑从手机拉取 | 选 B（ADB 拉取）；文案写「下载到电脑」 |
| 下载位置 | 每次弹保存框 | 固定 `Downloads\CastPane` + 打开文件夹 | 选 B，步骤短；路径明示 |

## 能力边界

| 能力 | 现成 API | 结论 |
|---|---|---|
| 列目录 | `adb shell ls -la <path>` | 能用；解析 toybox 输出 |
| 拉取文件 | `adb pull`（或 `exec-out cat`） | 能用；轮询本地文件大小算进度 |
| 推送文件 | `adb push` | 能用；解析输出/轮询远端大小算进度 |
| 递归文件夹 | `adb push` / `adb pull` 目录 | 能用；进度按文件/不确定态 |
| 读取大小 | `adb shell stat -c %s` | 能用（toybox） |
| 默认目录 | `/sdcard`、`/sdcard/Download` | 能用；`/sdcard` 指向 `/storage/emulated/0` |
| 受限目录 | `/sdcard/Android/data`、`/sdcard/Android/obb` | 权限拒绝，只能提示换目录 |
| 原生文件选择框 | Windows `GetOpenFileNameW`（comdlg32） | 能用；在主程序进程实现，不新增依赖 |
| 拖拽文件 | Tauri drag-drop 事件（绝对路径） | 能用；作为发送文件夹的入口 |
| 断点续传 | adb 原生不支持 | 不做；失败保留部分文件并提示 |

## 界面（若涉及）

- 竞品拆解：见 [file-transfer-competitor-teardown.md](file-transfer-competitor-teardown.md)（含截图）。
- 设计稿：`docs/design/v03-wireframe.html` / `docs/assets/v03-wireframe.png`。
- 首屏新增：状态行右侧一个紧凑 `文件` 入口（仅手机 `ready` 时出现）。
- 首屏可交互元素（≤ 5）：`更多`、最多 2 个设备行、主按钮、`文件` 入口。
- 为新增控件删掉的元素：设备行最多 3 → 2；不再为文件互传在首屏加第二排按钮。
- 二级页：文件页有返回、面包屑、刷新、发送、下载、打开文件夹、传输卡片；不占首屏。
